Keep the apartment colours in Google Calendar

Google Calendar ignores colours inside imported files: everything takes the colour of the calendar it is imported into. So give each apartment its own calendar, once:

  1. In Google Calendar, next to Other calendars click + → Create new calendar. Make three: "Aida 14", "Aida 37" and "Clotilde 28".
  2. Point at each new calendar in the left list → ⋮ → + (custom colour) and paste its colour:
    Aida 14 · #7FB36CAida 37 · #6F9FD0Clotilde 28 · #E0A066
  3. Click One file per apartment above. Then Settings → Import & export → Import each file into the calendar with the same name.

Each booking keeps the same ID in every file, so importing a newer file into the same calendar should update the bookings already there rather than duplicate them. If a change doesn't show, delete that booking in Google and import again.

Connect Gmail (one-time setup, about 15 minutes)
  1. Sign in to the Gmail account that receives the Airbnb, Booking.com and site emails (or the one you forward them to).
  2. Go to script.google.com → New project. Name it "Reservas Estoril".
  3. Replace the code in Code.gs with the contents of Code.gs. Click + → Script, name it Parser, and paste parser.js into it. Save.
  4. Choose setup in the function menu and press Run. Allow the permissions it asks for (Gmail, Sheets). It creates the sheet "Reservas Estoril · dados" and checks Gmail every 10 minutes.
  5. Open setPasswords, type a manager password and a cleaning password between the quotes, Run it, then delete the two passwords from the code and save.
  6. Run importHistory once to read the last 400 days of emails.
  7. Deploy → New deployment → type Web app. Execute as: Me. Who has access: Anyone. Copy the Web app URL.
  8. Paste that URL into API_URL near the bottom of index.html (or into Settings → Server & access on each device). Reload and log in.

"Anyone" only lets the page reach the script. No booking leaves it without the right password. The full guide is in SETUP.md.

Forwarding emails from another Gmail
  1. In the Gmail that gets the emails: Settings → Forwarding and POP/IMAP → Add a forwarding address → enter the Gmail that runs the script, and confirm the code Google sends there.
  2. Settings → Filters → Create filter. From: airbnb.com OR booking.com OR brevosend.com → Create → Forward it to that address.
  3. Forwarding by hand also works: forward any booking email to the script's Gmail and it is read within 10 minutes.
How emails become bookings
  • Airbnb: confirmations and reminders give the guest, country, dates, times, guests, code, total paid and your payout (shown as profit). Payout emails update the profit. Inquiries appear under Inquiries, not in the calendar.
  • Booking.com: guest messages give the name, dates, guests and booking number; a requested arrival time in the message becomes the check-in time. The total is not in these emails: type it in, or load the Booking export on the Import tab.
  • Site: requests come in as "Waiting Confirmation" with phone, email and notes. The site's total is usually only the cleaning fee: correct it once agreed.
  • Emails about the same booking are joined by their code. Anything you change by hand is kept.
  • Bookings with no apartment show "Pick apartment". Set it once per listing name in Listing names → apartment, or per booking.
Add a reservation by hand
  1. Import tab → Add a guest manually. Fill in name, apartment and dates, then Add to the list.
  2. When you are logged in it is saved on the server too, so it appears in the calendar on every device.
  3. Or paste the email text in Emails → Paste an email and press Save.
Keep the Excel workbook up to date

Load the workbook on the Import tab. Bookings from email appear in the review table next to the platform exports; the ones already in the sheet are marked "In sheet". Press Create updated workbook to add the new ones.

Passwords and the cleaning login
  • Give the cleaning password to the cleaning team. They see apartment, dates, times, number of guests and first name only, plus the laundry.
  • To change a password, run setPasswords again with new ones. Sessions end after 8 hours, or 30 minutes without use.
  • After 8 wrong passwords, login is blocked for 15 minutes.
